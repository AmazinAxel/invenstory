# D23. Analysis runs on the owner's OpenRouter login (key stored in the n8n workflow)

- **Decision:** When the app's model connection is OpenRouter, `invenstory-analyze` installs itself in a "direct"
  variant: one HTTP Request node calls OpenRouter's chat-completions endpoint with the key from the owner's login, on a
  small fixed model (`anthropic/claude-haiku-5.5`, changeable under Automations → Analysis). The key is written into
  that node's `Authorization` header and nowhere else. The credential variant (LLM chain bound to an n8n credential)
  stays for every other connection and is generated byte for byte as before, so `CORE_VERSION` is unchanged.
- **Why:** The owner wants insights and the "new action items" push while the app is closed, without creating an LLM
  credential in n8n by hand and without spending n8n Gateway credits (a small prepaid balance that n8n attaches by
  itself to model nodes created over MCP without a credential). n8n's MCP server cannot create credentials, so a
  workflow is the only place the app can hand n8n a key. Running analysis in the browser would keep the key on the
  device but stops when the app is closed.
- **Cost, accepted by the owner (to be stated in the terms):** the OpenRouter key is readable by anyone who can open
  that workflow in the owner's n8n; it stays in the workflow's version history and in archived copies after "Set up
  again"; it passes once through the `/mcp` proxy when the workflow is created; n8n's validator flags it
  (`HARDCODED_CREDENTIALS`, a warning). OpenRouter does not let the app create a separate capped key (that API needs
  a management key), so a spending limit is something the owner sets on OpenRouter's site.
- **Guards:** the chat agent can no longer read core workflows or their run data (`refuseCore` in `tools.ts`, by id
  and by name): a workflow read would put the key into the chat history and send it to the model provider. The key is
  never written to `inv_config`, and installer errors are redacted. Only OpenRouter keys are shared this way: keys for
  other providers stay on the device, and n8n cannot reach a local Ollama.
